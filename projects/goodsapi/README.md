# Goods API

REST API для управления товарами, написанный на **Go**.

Проект использует:
- **Go 1.22+** — язык программирования;
- **PostgreSQL** — база данных;
- **pgx** — драйвер для работы с PostgreSQL;
- **net/http** — стандартная библиотека для HTTP-сервера.

## 📂 Структура проекта

```text
goodsapi/
├── main.go                 # Точка входа приложения
├── go.mod                  # Зависимости и настройки Go-модуля
└── internal/
    ├── model/              # Модели данных (DTO)
    │   └── model.go
    ├── store/              # Слой доступа к данным
    │   ├── store.go        # Интерфейс GoodStore и ошибки
    │   ├── pg.go           # Реализация для PostgreSQL
    │   └── fake.go         # Фейковые хранилища для тестирования
    └── server/             # HTTP-слой
        ├── server.go       # Роутер и обработчики
        └── server_test.go  # Тесты HTTP-обработчиков
```

## 🚀 Запуск проекта

### Требования

Перед запуском необходимо установить:
- Go версии 1.22 или выше;
- PostgreSQL.

### Настройка базы данных

Укажи строку подключения через переменную окружения `DATABASE_URL`:

```bash
export DATABASE_URL="postgres://user:password@localhost:5432/dbname?sslmode=disable"
```

### Запуск сервера

Из корневой директории проекта выполни:

```bash
go run main.go
```

После успешного запуска сервер будет доступен по адресу:

```text
http://localhost:8080
```

## 🛠 Тестирование

Запуск всех тестов:

```bash
go test -v -cover ./...
```

Тесты HTTP-слоя используют фейковые реализации хранилища, поэтому для их запуска подключение к PostgreSQL не требуется.

Если в проекте реализованы интеграционные тесты, они могут дополнительно проверять работу с настоящей базой данных при наличии `DATABASE_URL`.

### Проверка сборки

Перед коммитом рекомендуется проверить, что весь проект успешно собирается:

```bash
go build ./...
```

## 🛣 API Endpoints

| Метод | Путь | Описание | Успешный ответ | Возможные ошибки |
|---|---|---|---|---|
| `GET` | `/health` | Проверка работоспособности сервера | `200 OK` | — |
| `GET` | `/goods` | Получение списка товаров | `200 OK` | `500` |
| `GET` | `/goods/{id}` | Получение товара по ID | `200 OK` | `400`, `404`, `500` |
| `POST` | `/goods` | Создание товара | `201 Created` | `400`, `500` |
| `PUT` | `/goods/{id}` | Полное обновление товара | `200 OK` | `400`, `404`, `500` |
| `DELETE` | `/goods/{id}` | Удаление товара | `204 No Content` | `400`, `404`, `500` |

### Коды ответов

- `200 OK` — запрос успешно выполнен.
- `201 Created` — ресурс успешно создан.
- `204 No Content` — операция выполнена без тела ответа.
- `400 Bad Request` — некорректный ID или данные запроса.
- `404 Not Found` — товар не найден.
- `500 Internal Server Error` — внутренняя ошибка сервера.

## 📦 Формат данных

### Создание товара — POST `/goods`

Пример JSON:

```json
{
  "name": "iPhone 15",
  "price": 999.99,
  "category_id": 1
}
```

### Обновление товара — PUT `/goods/{id}`

Используется аналогичный формат:

```json
{
  "name": "Samsung Galaxy S24",
  "price": 899.99,
  "category_id": 2
}
```

Поле `category_id` является опциональным и может принимать значение `null`.

## 🏗 Архитектура

Проект разделён на несколько слоёв:

- **model** — структуры данных приложения;
- **store** — интерфейс и реализации хранилища;
- **server** — HTTP-обработчики и маршрутизация;
- **main.go** — инициализация зависимостей и запуск сервера.

Для взаимодействия с базой данных используется интерфейс `GoodStore`. Это позволяет независимо тестировать HTTP-слой с помощью фейковых реализаций хранилища.

## 📝 Примечания

- Для работы приложения требуется настроенная база PostgreSQL.
- Переменная окружения `DATABASE_URL` должна содержать корректную строку подключения.
- Фейковые хранилища предназначены для тестирования.
- Все команды `go test` и `go build` выполняются из директории, содержащей `go.mod`.

Если проект находится внутри монорепозитория `avito-prep`, команды из корня репозитория могут выглядеть следующим образом:

```bash
go test ./projects/goodsapi/...
go build ./projects/goodsapi/...
```
