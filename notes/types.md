Указатели: Swap

| Вариант | Тело функции | Результат |
|---|---|---|
| без указателей | `a, b = b, a` | 1 2 — не работает |
| указатели без `*` | `a, b = b, a` | 1 2 — не работает |
| указатели с `*` | `*a, *b = *b, *a` | 2 1 — работает |

Почему первые два не работают: :
В Go всё передаётся копией: в варианте 1 — копии чисел,
в вариантах 2 и 3 — копии адресов.

1 и 2 меняют только свои копии, которые исчезают после выхода.
3 тоже получает копии адресов, но меняет не их, а то, что лежит
по этим адресам — то есть исходные x и y.

p1 := Point{1, 2}
p2 := p1
p2.X = 100
fmt.Println(p1.X)   

p3 := &p1
p3.X = 100
fmt.Println(p1.X)   

в первом 1 во втором сто так как в первом мы скопировали и передали занчение p1 p2, а во втором передали по ссылке значение p1


## Слайсы

Слайс — окно в массив: указатель на начало, длина, ёмкость.

- `cap` при переполнении растёт: 1, 2, 4, 8, 16, 32 — удвоение.
  Для больших слайсов рост замедляется.
- `append` может выделить новый массив, поэтому всегда `s = append(s, x)`.
- `a[1:3]` не копирует данные, а смотрит в тот же массив.
  `b[0] = 100` меняет `a[1]` — это одна ячейка.
- Функция, получившая слайс, может менять его элементы — изменения видны снаружи.
- Независимая копия: `slices.Clone(a[1:3])`.
- `append` в подслайс, у которого есть запас `cap`, перезапишет
  элементы исходного слайса.
## Мапы

- Создавать через `make(map[K]V)` или литерал `map[K]V{...}`.
- `var m map[string]int` без `make` — это nil-мапа.
  Читать из неё можно (вернёт ноль), а запись паникует:
  `panic: assignment to entry in nil map`.
- Отсутствующий ключ — не ошибка, возвращается нулевое значение.
- Отличить «ключа нет» от «значение ноль» — только через
  `v, ok := m[k]`: `ok == false`, если ключа нет.
- Порядок обхода `range` случайный и меняется между запусками.
  Нужен порядок — собери ключи в слайс и отсортируй.
  (`fmt.Println` печатает мапу отсортированной — это только печать.)
- Счётчик: `counts[w]++` — отсутствующий ключ стартует с нуля.

## Функции как значения

- Функцию можно положить в переменную и передать аргументом:
  `double := func(x int) int { return x * 2 }`.
- Тип функции пишется как её сигнатура без имени: `func(int) int`.
- При передаче — без скобок: `Apply(nums, double)`.
  `double` — сама функция, `double(3)` — её вызов.

## Apply: не портить входные данные

- Функция, получившая слайс, может изменить его элементы —
  вызывающий код увидит изменения (слайс смотрит в общий массив).
- Если функция должна вернуть результат, не трогая вход, —
  создавай новый слайс через `make` и пиши туда:

      result := make([]int, len(nums))
      for i, v := range nums {
          result[i] = f(v)
      }

- Читать — из входного слайса, писать — в новый.

## Замыкания

    func Counter() func() int {
        count := 0
        return func() int {
            count++
            return count
        }
    }

- Анонимная функция захватывает переменную `count`.
- `Counter` уже вернула управление, а `count` продолжает жить,
  пока на функцию есть ссылка. Go переносит такие переменные
  из стека в кучу.
- Каждый вызов `Counter()` создаёт новую `count`,
  поэтому у `c` и `d` счётчики независимы.
- Функция + захваченные ею переменные = замыкание.

## Стиль

- В `range` всегда `for i, v := range s`: `i` — индекс, `v` — значение.
- `x++` вместо `x += 1`.
- Короткое объявление `s := "..."` вместо `var s string` + присваивания.
- ## Методы

Метод — функция с приёмником, указанным перед именем:

    func (r Rect) Area() float64      // приёмник по значению
    func (r *Rect) Scale(k float64)   // приёмник по указателю

Это ровно те же функции, только записанные иначе:

    func Area(r Rect) float64
    func Scale(r *Rect, k float64)

Отсюда всё поведение:

- Приёмник по значению получает КОПИЮ. Изменения внутри метода
  наружу не видны — метод с таким приёмником не может менять объект.
- Приёмник по указателю получает адрес и меняет оригинал.

Вызов в обоих случаях выглядит одинаково — `r.Scale(2)`.
Go сам подставляет `&r`, когда метод требует указателя.
Поэтому по месту вызова разницу не видно, только по объявлению.

Правила:
- Метод что-то меняет → приёмник по указателю, без вариантов.
- Если хотя бы одному методу типа нужен указатель — делай указатель
  у всех методов этого типа, чтобы не было разнобоя.
- Большая структура → указатель даже для чтения, чтобы не копировать.
## Интерфейсы

- Интерфейс — список методов. Тип удовлетворяет ему автоматически,
  если методы есть. Никаких implements.
- Интерфейс хранит значение, но не его поля: у него можно вызвать
  только объявленные методы.
- Набор методов: метод на `*T` принадлежит типу `*T`, а не `T`.
  Значит `T` интерфейсу не удовлетворяет — в слайс кладут `&T{...}`.
  Обратное работает: метод на `T` доступен и через `*T`.
- Практика: методы с приёмником-указателем → в интерфейс кладёшь указатели.
- `fmt.Stringer` — интерфейс с методом `String() string`.
  Есть он у типа — `fmt.Println` печатает его результат вместо полей.
  Ничего регистрировать не нужно.
